# GL-Agent 功能设计方案

> 运行在 GL.iNet 全系路由器上的自然语言配置 Agent，注入 GL 固件**原生界面**（SDK4，非 LuCI）。
> 本文是设计评审稿，等待确认后再进入实现。

---

## 0. 一句话定义

在 GL 路由器原生后台里长出一个「AI 助手」页：用户用中文说「把 5G WiFi 密码改成 abc12345，然后把访客网络带宽限制到 5Mbps」，Agent 通过用户自配的大模型 API 理解意图，调用路由器自身的 RPC 能力执行，全过程流式可见、可确认、可回滚。

---

## 1. 现场调研结论（实测 192.168.1.1 · GL-MG1300）

这些是设计的物理边界，全部实测确认，不是假设：

| 项目 | 实测值 | 对设计的影响 |
|---|---|---|
| 固件 | GL 固件 **4.10.0** / OpenWrt 22.03.4 | 注入目标 = GL SDK4 UI |
| 平台 | ramips **mt7621** / **mipsel_24kc** / Linux 5.10.176 | 无法跑 Node/Python，编译产物需 mipsel |

| ubus 服务 | `network` `network.interface.*` `network.wireless` `wifi` `repeater` `clients`/`gl-clients` `firewall` `dns` `qos` `kmwan` `parental-control` `tailscale` `system` `service` `uci` `rc` `log` `sms_manager` `modem` `tethering` `timer` `vlan` `led` … | 能力矩阵直接由 ubus 服务清单驱动 |
| 脚本运行时 | **Lua 5.1.5** + `cjson` + `uci` + `ubus` + `nixio` + `uloop` + **`resty.http`（lua-resty-http 已在机）** + `gl.*` + `oui.*`；`curl 7.88`；**无 python / 无 node** | Agent 内核用 Lua 写在 nginx 内 |

**关键结论：本项目不需要任何新运行时。** nginx 已带 lua + lua-resty-http，路由器能直接 HTTPS 出网调大模型，UI 是 Vue 2 且暴露了完整原生组件库。这三点决定了架构。

## 3. 总体架构

```
┌─────────────────────────── 浏览器（GL 原生后台） ───────────────────────────┐
│  gl_home.html                                                              │
│   ├── <script src="/js/gl-agent-boot.js">   ← 注入：注册 Agent 视图入口     │
│   └── <script src="/js/app.*.js">           ← GL SDK4 SPA（Vue 2.6.12）     │
│                                                                             │
│  #/gl-agent  聊天页（Vue 2 组件，复用 gl-card / gl-button / gl-switch…）    │
│   ├── SSE  EventSource ←── 流式 token / 工具事件 / 确认请求                  │
│   └── POST /rpc  (call: gl_agent.*)  ←── 配置、会话、审批回复                │
└─────────────────────────────────────────────────────────────────────────────┘
                                    │  nginx (同一进程、同一证书、同一会话)
┌───────────────────────────────────▼─────────────────────────────────────────┐
│  nginx · location = /gl-agent/stream   (content_by_lua_file)                │
│  ┌───────────────── Agent Core (Lua 5.1) ─────────────────┐                 │
│  │ ①意图理解  ②规划  ③工具调用  ④结果回灌  ⑤循环(≤N步)     │                 │
│  │  LLM Client: lua-resty-http 流式 SSE，OpenAI/Anthropic/ │                 │
│  │              Gemini 三种协议适配，支持自定义 base_url    │                 │
│  │  Tool Registry: 声明式单一事实源（schema+映射+风险级）    │                 │
│  │  Policy: readonly / ask / auto  +  确认闸门 + 限流       │                 │
│  │  Journal: 变更前快照 → 一键回滚                          │                 │
│  └────────────────────────┬────────────────────────────────┘                 │
│  nginx · location = /rpc  →  /usr/lib/oui-httpd/rpc/gl_agent  (配置/会话)    │
│                           │                                                  │
│                    ubus / oui.rpc（与原生 UI 完全同一条链路）                 │
│                           ▼                                                  │
│   network · wifi · firewall · qos · dns · clients · system · service …       │
└─────────────────────────────────────────────────────────────────────────────┘
        持久化：/etc/gl-agent/{config.json, sessions/*.json, journal.jsonl}
```

### 3.1 为什么 Agent 内核放在 nginx-lua 里（而不是独立守护进程）

- nginx 已带 lua 模块与 `lua-resty-http`，`ngx.socket.tcp` 在等待网络时**让出事件循环**，SSE 流式读取不阻塞其他请求；
- 零新增常驻内存（省掉第二套 Lua VM + 状态机），对 52 MB 可用内存最友好；
- 直接复用 `/rpc` 的会话与鉴权，不新开端口、不新增攻击面；
- 工具执行走 `oui.rpc` / `ubus`，与原生 UI 同一条链路，**能力天然对齐、不会出现「UI 能改但 Agent 改不了」**。

### 3.2 长连接与超时

在 `/etc/nginx/gl-conf.d/gl-agent.conf` 里追加自己的 `location`，独立设置 `client_body_timeout` / `send_timeout` / `keepalive_timeout`，不受全局 8s keepalive 影响。SSE 端点心跳保活，前端断线自动重连并续接会话。

### 3.3 工具注册表 = 单一事实源

一个 Lua 表同时驱动三件事：**LLM 的 function schema**、**执行映射（ubus/RPC 调用）**、**UI 展示（名称/图标/参数渲染）**。新增能力只改一处，永不漂移。

```lua
{
  name = "wifi.set_guest",
  group = "wireless",
  risk = "medium",                 -- low(读) / medium(改) / high(危险)
  desc = "开启或关闭访客网络，并设置 SSID / 密码 / 加密方式",
  params = { enabled="bool", ssid="string", key="string", encrypt="enum:..." },
  map = { rpc = "wifi", method = "set_guest_wifi" },
  reversible = true,
  preview = "访客网络 → {enabled}, SSID「{ssid}」"
}
```

## 4. 功能清单

### 4.1 对话式配置（核心）

- **自然语言直改**：一句话改 WiFi 名称/密码/信道/带宽、开关访客网络、限速、改 DNS、加端口转发、禁某设备上网、重启、切网络模式……
- **多轮追问**：信息不全时反问你（「没说改 2.4G 还是 5G，两个都改吗？」），而不是瞎猜。
- **先读后写**：默认先查当前状态再动手；「现在 WiFi 什么情况」这类只读问答不产生任何变更。
- **意图 → 计划卡片**：执行前用一张「变更预览卡」列出将要做的每一步与参数差异（旧值 → 新值）。
- **干跑（Dry-run）**：可要求「只告诉我你会怎么做，先别改」。
- **解释与教学**：每个动作用一句人话说清影响，并可展开看实际 RPC 调用（透明可审计）。

### 4.2 执行可见性（Agent 的「手」）

- **时间线事件流**：`思考中… → 调用 wifi.get_status → 已读取：当前 2.4G=GL-MG1300-xxx → 调用 wifi.set_2g → 成功 → 完成`。
- **工具调用卡**：可折叠，展开显示入参、原始返回（截断）、耗时、成功/失败。
- **失败自愈**：参数错误/RPC 报错时自动读回真实状态重试一次，仍失败则用人话报告原因。
- **中断**：随时「停止」，已完成的变更是既定事实，未执行的不再做。

### 4.3 安全与可控（让用户敢用）

- **三级权限模式**：
  - `只读`：只允许查询类工具，写操作直接拒绝；
  - `询问`（默认）：中/高风险操作弹确认卡，低风险（读）自动放行；
  - `自动`：全部自动执行（高风险项仍会二次确认，可关）。
- **确认卡**：倒计时（默认 30s 超时视为取消）、影响说明、参数明细、「不再询问此类」勾选。
- **一键回滚**：每次写操作前自动快照相关 UCI 配置到 journal，提供「撤销上一步 / 撤销本次会话全部变更」。
- **危险操作硬拦截**：恢复出厂、固件升级、重启、关机、改管理密码、改 LAN 网段、开放 WAN 管理端口——永远走确认，`自动`模式下也不例外。
- **命令白名单**：不接受模型自由生成 shell；只执行注册表里的工具，shell 类工具模板化 + 参数校验转义。
- **预算与熔断**：单轮最多 N 步工具调用（默认 12）、单轮 token 上限、请求频率限制；防止模型死循环烧钱。
- **审计日志**：`/etc/gl-agent/journal.jsonl` 记录时间、会话、工具、参数、结果、是否用户确认。

### 4.4 模型与应用配置

- **多配置档案**：可存多套（名称 / base_url / api_key / model / 协议 / 温度 / 最大 token），一键切换。
- **协议适配**：OpenAI 兼容（OpenAI、DeepSeek、Moonshot、硅基流动、通义、智谱、本地 Ollama/vLLM…）、Anthropic Messages、Google Gemini。
- **连接自检**：填完点「测试连接」，返回实际延迟与模型回显，失败给出人话原因（DNS/证书/401/超时/余额）。
- **高级项**：自定义 HTTP 头、代理地址（支持走本地代理/自建网关）、超时、是否发送设备上下文。
- **密钥安全**：`/etc/gl-agent/config.json` 权限 0600，UI 上掩码显示（只显示后 4 位），永不进日志。
- **成本显示**：可选显示每轮 token 用量与估算花费。

### 4.5 会话与记忆

- **多会话**：左侧历史抽屉，新建/重命名/删除/搜索；标题由模型自动摘要。
- **持久化**：`/etc/gl-agent/sessions/<id>.json`，重启路由器后仍在。
- **上下文裁剪**：保留最近 N 轮 + 滚动摘要，控制 token 与内存。
- **引用上下文**：可勾选把「当前设备状态快照」注入上下文（型号、固件、WAN 状态、在线客户端数）。
- **会话级工具许可**：「本次会话允许直接改 WiFi」。
- **导出**：导出为 Markdown/JSON（便于排查与分享）。

### 4.6 Agent 能力矩阵（工具清单）

| 分组 | 能力 | 风险 |
|---|---|---|
| 概览/诊断 | 系统信息、内存/Flash/负载、温度、运行时长、WAN 状态、公网 IP、在线客户端列表、DHCP 租约、WiFi 状态与信道、日志读取 | 只读 |
| 无线 | 改 SSID/密码/加密、2.4G/5G 开关、信道与带宽、发射功率、访客网络增删改、隐藏 SSID、随机 MAC、WiFi 定时开关、扫描周边 AP 并给信道建议 | 中 |
| 网络 | LAN 网段、DHCP 地址池与租期、静态路由、静态 DNS/DoH、UPnP、IPv6 开关、MTU、网络模式切换（路由/AP/桥接/中继）、多 WAN 与优先级、端口转发/DMZ/端口触发、MAC 绑定与克隆 | 中~高 |
| 无线中继 | 扫描并连接上游 WiFi、中继保存列表 | 中 |
| 客户端管控 | 拉黑/放行设备、改名、限速（上下行）、查看流量、家长控制（时段+网站分类）、分组 | 中 |
| 服务 | WireGuard/OpenVPN 客户端与服务器的启停与配置、Tailscale、DDNS、AdGuard、ZeroTier、Tor、Samba/NAS | 中 |
| 定时任务 | 定时重启、定时开关 WiFi、自定义计划任务 | 中 |
| USB/热点 | 文件共享开关、蜂窝/热点模式、短信读取与转发 | 中 |
| 设备专属 | **能力探测动态生成**：风扇与温控曲线（fanctrl 类机型）、LED 开关、按键自定义、PoE、电量、蜂窝信号与锁频 | 中 |
| 系统 | 改时区/NTP、改主机名、改管理密码、重启、关机、恢复出厂、备份/恢复配置、固件检查（升级永远人工确认） | 高 |

> 全系适配策略：**能力探测（capability probing）** 而非机型硬编码。启动时枚举 ubus 服务 + 探测 `/usr/lib/oui-httpd/rpc/*` 与 `menu.d/*.json`，生成「本机能力清单」；只有本机存在的能力才会出现在 LLM 的工具表里——保证「同一条指令在 MT3000 上与在 MG1300 上语义一致」，个性化能力自动收敛。

### 4.7 主动与自动化

- **智能建议**：检测到拥堵信道、弱信号客户端、异常流量时给一条可点的建议卡。
- **定时巡检**（可选）：每日生成一份「路由器健康简报」，异常才推送。
- **快捷指令**：可把常说的话存成快捷短语（首页 Chips 可编辑）。
- **分享**：把一个已跑通的对话导出成「一键任务」（本质是参数化工具序列），同型号可导入执行。

## 5. 界面设计（现代、美观、与原界面融合）

### 5.1 融合策略：不是「像原界面」，而是「就是原界面」

1. **组件同源**：直接用 `<gl-card>` `<gl-title>` `<gl-button>` `<gl-switch>` `<gl-tips>` `<gl-dropdown>` `<gl-progress>`，与原页面同一个 Vue 实例的全局组件；
2. **令牌同源**：颜色只使用 `var(--primary)` `var(--text-regular)` `var(--background-card)` `var(--divider)` `var(--success-background)`… 换主题（default / **dark** / classic）自动跟随，零硬编码色值；
3. **导航同源**：`menu.d/gl-agent.json` 官方菜单机制，出现在原生侧边栏「系统」分组，自带原生图标与高亮态；
4. **i18n 同源**：`/www/i18n/gl-sdk4-ui-gl-agent.<lang>.json`，跟随后台语言切换，简繁英日德西意全覆盖；
5. **壳层同源**：顶部标题栏、面包屑、卡片阴影/圆角/间距全部沿用原页面骨架。

### 5.3 动画与交互细节（"丝滑"落到具体参数）

| 元素 | 规格 |
|---|---|
| 消息入场 | `translateY(8px) + opacity 0→1`，`cubic-bezier(.22,1,.36,1)` 320ms |
| 流式文字 | 40ms 节奏补帧渲染（`requestAnimationFrame` 批量，避免逐 token 抖动），尾部 2px 竖线光标闪烁 1s |
| 思考指示 | 三点错相呼吸（0/160/320ms 延迟），出现/消失 200ms 淡入淡出 |
| 工具卡展开 | `max-height + opacity` 240ms，箭头旋转 180° |
| 确认卡 | 从底部 12px 上浮 + 轻微 scale `.98→1`，240ms；倒计时环 `stroke-dashoffset` 线性递减 |
| 发送/停止 | 按钮 morph：圆形 ➤ ↔ 方形 ■，`border-radius` 与图标 200ms 交叉淡入 |
| 侧栏抽屉 | 320ms 位移 + 遮罩 `rgba(16,18,35,.24)` 淡入（`--mask` 令牌） |

| 主题切换 | 全部使用 CSS 变量，切换瞬间跟随，无需刷新 |

## 7. 部署与安装

- **安装包形态**：`opkg` 包（ipk，适配 OpenWrt 22.03 / GL 4.x）+ 一键 Shell 安装脚本（适配不同固件与 apk 体系的机型）+ 图形化安装（原生 UI 上传装包）。
- **安装位置**：后端 `/etc/gl-agent/`、RPC `/usr/lib/oui-httpd/rpc/gl_agent`、菜单 `/usr/share/oui/menu.d/gl-agent.json`、i18n `/www/i18n/gl-sdk4-ui-gl-agent.*.json`、前端 `/www/views/gl-sdk4-ui-gl-agent.common.js.gz` + `/www/js/gl-agent-boot.js`，并**先备份** `gl_home.html` 再注入。
- **卸载**：完整还原 `gl_home.html`、清掉注入 script 与菜单/i18n/视图文件、恢复 nginx 配置，不留残留。提供 `gl-agent uninstall --purge`（含密钥与会话清理）。
- **升级**：保留配置与密钥，覆盖代码；注入部分幂等（先检测避免重复注入）。
- **降级保护**：注入脚本全程 `try/catch`，任何异常静默放弃，**绝不影响原生后台可用性**；卸载脚本可在 SSH 下单条命令执行。

## 9. 安全设计（对抗「模型乱来」）

1. **能力即权限**：模型只能选注册表里的工具，无法凭空执行命令。
2. **工具结果隔离**：RPC/日志/SSID 等外部文本一律作为「数据」注入，包裹标记并提示模型不得当作指令执行（防提示注入）；SSID、备注名等字段做长度与字符清洗。
3. **写前快照**：任何写操作前保存相关 UCI 段 → 一键回滚。
4. **参数强校验**：每个工具的参数在 Lua 侧按 schema 二次校验（类型、范围、正则、CIDR/掩码/密码强度），不信任模型输出。
5. **网络白名单**：只在配置的 base_url 上发起请求；可选「仅允许 HTTPS」；不向模型发送密钥与完整客户端 MAC/主机名（可配置脱敏）。
6. **密钥保护**：0600 权限、UI 掩码、日志脱敏、导出时排除。
7. **限流熔断**：单轮步数、单轮 token、每分钟请求数三重上限；连续失败自动停止。
8. **审计可追溯**：所有变更落 journal.jsonl（含是否经人工确认）。

## 11. 已确认决策（评审定稿）

| 决策点 | 结论 |
|---|---|
| **首版范围** | **强场景先做透**：WiFi / 网络 / 客户端 三组（含读写）+ 只读诊断全量，打磨到可日常用，再按能力矩阵铺开 |
| **默认权限模式** | **询问模式**：只读自动放行；中风险弹确认卡；高风险（恢复出厂/升级/重启/改管理密码）强制二次确认 |
| **原生页面增强** | **要做，但默认关闭**，在 Agent 设置里一键开关（概览页卡片 + 顶部快捷按钮） |
| **模型服务预设** | **不预置服务商**，只提供「自定义 base_url」；协议选 OpenAI 兼容 / Anthropic / Gemini，UI 内提供 DeepSeek、硅基流动等作为**可一键填入的模板**（仅填 base_url 与模型名，不留任何内置密钥与默认供应商绑定） |
| **代理支持** | 一等公民配置项：`代理模式（关闭/系统/手动）` + `代理地址`，适配自建中转站与本地代理 |
| **与 glinjector 共存** | 共存，互不干扰（不同文件/菜单项/nginx location） |
| **菜单归属** | 原生侧边栏「系统」分组（与 fanctrl 一致，index 25，避开 glinjector 的 22 与 fanctrl 的 24） |

### 11.1 首版（P0–P3）工具清单冻结

**只读（自动放行）**
`system.get_status` · `system.get_info` · `system.get_load` · 温度/内存/Flash · `network.get_status` · WAN 状态与公网 IP · `clients.get_status`（在线设备+流量）· DHCP 租约 · `wifi.get_status`（双频 SSID/信道/加密/功率）· WiFi 扫描与信道占用 · `logread` 关键日志 · `repeater` 扫描结果

**写入（询问模式确认）**
`wifi.set_2g` / `wifi.set_5g`（SSID/密码/加密/信道/带宽/功率/隐藏）· `wifi.set_guest`（访客网络增删改）· `network.set_dhcp`（地址池/租期/静态 DNS）· `firewall` 端口转发增删 · `clients` 设备改名 / 限速 / 拉黑放行 · 客户端管控与家长控制基础项

**高风险（强制确认，自动模式也确认）**
重启 · 恢复出厂 · 改管理密码 · 改 LAN 网段 · 固件升级入口（只跳原生页面，不代执行）

**首版不含**（P5 铺开）：VPN 客户端/服务端配置、DDNS、Tailscale、AdGuard、NAS/Samba、蜂窝与短信、设备专属（风扇/LED/PoE）
